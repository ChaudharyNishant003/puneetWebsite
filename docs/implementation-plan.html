Phase 1 की e-commerce website और admin panel बनाने का plan. Design D (Jaipur Kurti structure + research doc के सुधार) पर based है. Approve होते ही इसी क्रम में build होगा.

1. Scope एक नज़र में

Phase 1 में है

  • Storefront: home, collections, search, product page, cart, wishlist
  • OTP login, guest checkout, Razorpay, COD + OTP
  • Local delivery + Shiprocket
  • Orders, exchange, photo reviews + fit rating
  • SMS/email notifications, GST invoice
  • Admin: Owner/Staff, products, stock, orders, CMS, reports
  • SEO, analytics, legal pages

Phase 2 में है (अभी नहीं)

  • WhatsApp (click-to-chat, API, cart recovery)
  • In-store POS/billing
  • Phone-number loyalty
  • Store pickup, दुकान पर exchange/alteration, reserve & try
  • Video-call shopping

Schema में इनके लिए जगह पहले से रखी जाएगी (जैसे Customer.phone unique ID, Order.channel), ताकि बाद में migration छोटा रहे.

COD के rules (Settings से बदल सकते हैं)

  • COD सिर्फ ₹X तक (default ₹3,000). Pincode पर codAllowed भी check होगा
  • Order place करने से पहले phone पर OTP
  • एक phone पर 2 से ज़्यादा RTO हुए तो उस phone पर COD बंद
  • Prepaid पर discount (default 5%, max ₹150)

8. Milestones और acceptance criteria

Approve होने के बाद सारे milestones बिना रुके लगातार बनेंगे. हर milestone के अंत में E2E tests pass होने चाहिए.

M0: Setup

Git init, feature/mvp branch, Next.js + Tailwind + Prisma, design tokens (Design D), lint, Vitest/Playwright, .env.example, Railway project + Postgres.

✓ Local पर app चलता है, DB connect है, CI script (lint + typecheck + test) pass है

M1: Data model + dummy seed

पूरा Prisma schema, migrations, seed script (section 2), SVG placeholder generator, demo:purge.

✓ npm run seed से ~80 products, variants, reviews, orders बन जाते हैं; purge से सब साफ हो जाता है

M2: Admin panel

Admin login + roles, products CRUD, variants/stock, image upload, CSV import/export, orders list, coupons, pincodes, settings, CMS blocks, audit log.

✓ Staff login से reports और users नहीं खुलते. Admin से बदला गया product storefront पर दिखता है. CSV से 50 products import हो जाते हैं

M3: Storefront (browse)

Header/menu/bottom nav, home (CMS), collection page + filters + sort, product page (पूरा spec), size chart, recently viewed, wishlist (guest + login), Visit Store, legal pages, SEO (schema, sitemap, OG).

✓ Mockup D से मेल खाता है. 360px पर horizontal scroll नहीं. Filters सही result देते हैं. Lighthouse mobile ≥ 85 (dummy data पर)

M4: Search

Full-text + trigram, autocomplete, synonyms (shaadi, maa, office, garmi, sasta…), "under ₹N" parsing, search overlay.

✓ Doc के 6 test queries (जैसे "office ke liye cotton kurti under 1500") सही products लाते हैं

M5: Cart, OTP, Checkout, Payments

Cart drawer (free-shipping bar), OTP login/guest, addresses, pincode से delivery mode + ETA, coupons, Razorpay (webhook), COD + OTP + limits, order confirmation, stock reserve/decrement.

✓ Mock और Razorpay test mode में prepaid और COD दोनों orders पूरे होते हैं. Payment fail पर stock वापस आता है. Webhook दोबारा आने पर भी duplicate order नहीं बनता

M6: Fulfilment + notifications

Admin order flow, Shiprocket (AWB, tracking webhook), local delivery status, GST invoice PDF, SMS + email templates (order, shipped, delivered, review request).

✓ Order से Delivered तक का पूरा flow admin से चलता है. हर status पर mock SMS और email निकलता है. Invoice में GST सही है

M7: Account, exchange, reviews

My orders, tracking, exchange request (7-day window, innerwear block, पहला free), reviews (verified buyer, fit rating, photos) + moderation.

✓ 8वें दिन exchange का button नहीं दिखता. Innerwear पर exchange का option नहीं आता. Approve होने पर review product page पर दिखता है

M8: QA, deploy, report

Full E2E suite, mobile QA (360/390/414), accessibility basics, content QA (placeholders, टूटे links), security review (auth, rate limits, webhook signatures), Railway deploy नई branch से, HTML build report.

✓ सारे tests pass हैं. Railway URL पर पूरा demo चलता है. Build report आपको मिलती है

9. Testing और QA

  • Unit: pricing (coupon, prepaid discount, COD fee, GST), exchange window, search parser, COD eligibility
  • E2E (Playwright, mobile viewport): browse → PDP → cart → OTP → prepaid order; COD order; payment fail; exchange; review; admin order flow
  • Security: OTP rate limit + attempts, admin routes पर role guard, Razorpay/Shiprocket webhook signature, price हमेशा server पर calculate होगा (client पर भरोसा नहीं)
  • Content QA checklist: हर badge policy से मेल खाए, कोई placeholder न दिखे, links ठीक हों, MRP असली हो

10. Git और deploy workflow

  1. D:\PuneetWebsite में git init, master खाली baseline रहेगा. उसे कोई नहीं छुएगा
  2. सारा build feature/mvp पर होगा. हर push message में नाम, वो क्या करता है, और उसमें शामिल सब चीज़ों की list होगी
  3. Deploy के लिए नई branch (deploy/mvp-1) बनेगी, Railway पर as-is deploy होगा, test होगा, fix local पर होंगे
  4. HTML report के साथ आपके approval के बाद ही merge होगा
  5. Railway के लिए Windows वाली सावधानियां: .gitattributes (LF), .railwayignore
