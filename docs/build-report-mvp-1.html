E2E suite में क्या चेक हुआ

  • COD order शुरू से अंत तक, invoice PDF के साथ; prepaid fail के बाद bag बचा रहता है और retry सफल होता है; COD limit का साफ कारण दिखता है

Testing में पकड़े और ठीक किए गए bugs

  • Payment method बदलते ही "Place order" दबाने पर पुरानी कीमत चली जाती थी और order रुक जाता था। अब नई कीमत आने तक बटन बंद रहता है।
  • Search की कमियां: suit वाली query में पुरुषों की sherwani आ रही थी, और "bacche ke kapde" पर कोई result नहीं आता था। Search को score से क्रम देने वाला बनाकर दोनों ठीक किए।
  • Security: emails में ग्राहक का लिखा नाम escape किया; banner links में // से बाहर की site पर redirect रोका; server-action files से बिना login-check वाले helpers हटाए।

ईमानदारी से: जो अधूरा है या ध्यान देने लायक है

  • Performance Mobile Lighthouse performance इस मशीन पर 73–76 आया (plan में लक्ष्य ≥85 था)। वजहें: dummy SVG images का rendering खर्च, और मशीन की धीमी CPU व memory की कमी (C: drive भरी है)। असली photos के साथ Railway URL पर PageSpeed Insights से दोबारा मापना है।
  • Mock Razorpay, MSG91, Shiprocket, Resend और Cloudinary अभी test mode में हैं। Keys आने पर सिर्फ env variables डालने होंगे और DEMO_MODE हटाना होगा।
  • Placeholders दुकान का नाम, पता, फोन, GSTIN, "Since 1998" और policy का text placeholder हैं। Policy pages पर इन्हें "[Placeholder]" लिखकर चिह्नित किया गया है।
  • Uploads Cloudinary न होने पर admin से डाली गई photos server की disk पर जाती हैं, जो Railway पर हर deploy के साथ मिट जाएंगी। असली photos डालने से पहले Cloudinary जोड़ना ज़रूरी है।
  • Local मशीन C: drive लगभग पूरी भरी है। इसी वजह से Docker अटका और Next.js memory की कमी से crash हुआ। Docker/WSL को आपकी मंज़ूरी से बंद किया गया है (Kutumb के local containers भी बंद हैं)।
