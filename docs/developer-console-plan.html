Developer Console: गुप्त control panel

मकसद: website और admin panel के हर feature को developer अपनी pricing के हिसाब से ON या OFF कर सके, owner account पर पूरा नियंत्रण रख सके, और owner या staff को developer के होने का कोई पता न चले।

1. आपके फैसले (जिन पर यह plan बना है)

विषयफैसला
Console कहांइसी website में, एक गुप्त URL पर। कोई और खोले तो उसे साधारण "Page not found" दिखे।
बंद feature कैसे दिखेपूरी तरह गायब: न menu, न बटन। Page का URL सीधे खोलने पर भी "Page not found"।
Pricingसिर्फ feature checklist (अलग plans नहीं)। हर feature का अपना ON/OFF।
OFF का असरहर feature के दो अलग switch: Admin panel में और Website पर।
Developer loginEmail, फिर password, फिर email OTP। Email service जुड़ने तक OTP screen पर दिखेगा (demo की तरह)।
Owner controlsOwner/Staff का login बंद या चालू करना, password reset, पूरी website बंद (maintenance), "Owner बनकर देखना", staff की गिनती सीमित करना।
Logsअभी नहीं चाहिए (बाद में जोड़ सकते हैं)।

2. Owner को developer का पता क्यों नहीं चलेगा

  • गुप्त URL: console का पता server की setting (DEV_CONSOLE_PATH) से आता है, जैसे /k7x-ops-29fd। यह code, menu, sitemap या robots.txt, कहीं नहीं लिखा होगा। गलत पता डालने पर वही 404 दिखेगा जो किसी भी गलत page पर दिखता है।
  • अलग login system: developer account एक अलग table में होगा। वह Admin → Users की list में कभी नहीं आएगा, और developer का cookie भी अलग होगा।
  • कोई निशान नहीं: developer के बदलाव owner की "Recent admin activity" में नहीं जाएंगे। "Owner बनकर देखना" के समय किया गया काम भी owner के नाम से दर्ज नहीं होगा।
  • बंद feature = कभी था ही नहीं: menu से गायब, page 404, बटन गायब, और server पर action भी बंद। अगर कोई पुराने link या किसी trick से कोशिश करे, तो उसे साधारण "Page not found" या "Something went wrong" मिलेगा, "आपका plan नहीं है" जैसा कुछ नहीं।
  • Maintenance और login बंद: owner को सिर्फ साधारण संदेश दिखेंगे, जैसे "Site is under maintenance" या "Your account is disabled. Please contact support"। उनमें developer का कोई ज़िक्र नहीं होगा।
ईमानदार सीमा: जिसके पास server (Railway) या GitHub code का access है, वह देख सकता है कि console मौजूद है। इसलिए Railway और GitHub का access सिर्फ आपके पास रहना चाहिए, owner को नहीं देना। Owner के सिर्फ website और admin panel इस्तेमाल करने तक उसे कुछ पता नहीं चलेगा।

3. Developer Console में क्या होगा

A. Feature Checklist

  • नीचे section 5 के सारे features, groups में
  • हर feature के साथ Admin और Website के switch
  • "सब ON", "सब OFF" और "Default" बटन
  • बदलाव तुरंत लागू हों (अगले page load पर)
  • हर feature के आगे छोटा विवरण कि OFF करने पर क्या बदलेगा

B. Owner / Staff Control

  • हर admin user: login बंद या चालू करना, password reset
  • Staff की अधिकतम गिनती (0 रखें तो staff बनाने का option गायब)
  • Owner बनकर देखना: एक click में admin panel owner की नज़र से खुल जाए, बिना उनका password जाने
  • उनका last login कब हुआ

C. Website Control

  • Maintenance mode: पूरी website पर "We'll be back soon", सिर्फ चुने हुए pages या पूरी site
  • Admin panel भी साथ में बंद करना हो तो उसका अलग switch
  • Maintenance का संदेश बदल सकें

D. Developer Account

  • Email, password और email OTP से login (email service जुड़ने तक OTP screen पर दिखेगा)
  • 5 गलत कोशिशों के बाद 30 मिनट का lock
  • Session 12 घंटे तक
  • Developer password बदलना

4. OFF करने पर असल में क्या होगा (enforcement)

  1. Menu: Admin menu सिर्फ ON वाले modules दिखाएगा।
  2. Page: बंद module का page खोलने पर वही 404 आएगा जो किसी भी गलत page पर आता है।
  3. बटन: page के अंदर के बटन (जैसे "Book courier & ship" या "Bulk import") भी गायब होंगे।
  4. Server पर रोक: हर admin action और हर API call से पहले feature की जांच होगी। सिर्फ UI छिपाना काफी नहीं है, क्योंकि कोई जानकार व्यक्ति सीधे action भेज सकता है।
  5. Website: website वाले switch से ग्राहक के लिए वो सुविधा हट जाएगी। जैसे Coupons OFF करने पर checkout में coupon का box नहीं दिखेगा, और पहले से bag में लगा coupon अपने-आप हट जाएगा।
  6. Data सुरक्षित: feature OFF करने पर कुछ delete नहीं होगा। वापस ON करते ही सब पहले जैसा मिलेगा।
  7. Speed: switches memory में cache होंगे (हर page पर database query नहीं होगी), और बदलने पर तुरंत refresh होंगे।

7. Technical ढांचा (संक्षेप में)

  • नई tables: DevUser (developer login), DevOtp, FeatureFlag (key, adminOn, siteOn), SiteControl (maintenance, staff limit)। Owner के admin में इनका कोई ज़िक्र नहीं होगा।
  • Feature registry: एक file में हर feature का key, नाम, विवरण और group। यही console की checklist भी बनाएगी और code की हर जांच भी यहीं से होगी, ताकि दोनों कभी अलग न हों।
  • Checks: isOn("coupons", "site") जैसे helper। Admin layout का menu, हर admin page, हर server action और हर storefront component इसी helper से जांच करेगा।
  • Middleware: maintenance mode और गुप्त path का guard।
  • Impersonation: owner के नाम से एक अलग तरह का session, जिसमें audit log में लिखना बंद रहेगा।
  • Setup: पहला developer account server setting (DEV_EMAIL, DEV_PASSWORD) से बनेगा, seed में नहीं, ताकि demo data में उसका निशान न रहे।

9. ध्यान देने लायक बातें

  • सुरक्षा जब तक email service नहीं जुड़ती, developer OTP screen पर दिखेगा। तब तक सुरक्षा असल में गुप्त URL, लंबे password और lock पर टिकी है। Email जुड़ते ही OTP अपने-आप email पर जाने लगेगा।
  • Logs आपने अभी logs नहीं मांगे। Developer के अपने बदलावों का एक छोटा रिकॉर्ड फिर भी रखना चाहता हूं, ताकि आप देख सकें कि कौनसा switch कब बदला। यह owner को कभी नहीं दिखेगा। आप मना करें तो यह भी नहीं रखूंगा।
  • Core "Orders management" और "Products add/edit" OFF करने पर दुकान चल ही नहीं पाएगी, इसलिए console उन पर एक चेतावनी दिखाएगा। OFF फिर भी किया जा सकेगा।
